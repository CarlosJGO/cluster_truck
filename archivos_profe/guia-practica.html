01

Prepara tu PC

Tu PC es el Cliente: envía las órdenes al cluster y recibe los resultados.

Descomprime el archivo practica-dask.zip en C:\practica-dask. Luego abre PowerShell y crea un entorno de Python para la práctica:

Tu PCPowerShell
cd C:\practica-dask
python -m venv venv
.\venv\Scripts\Activate.ps1

pip install -r requisitos.txt
Tus versiones deben ser las mismas del clusterSi tu profesor te da su propio requisitos.txt, usa ese. Si las versiones de tu PC no coinciden con las de los workers, el paso 3 te avisará con un error Mismatched versions.

Si PowerShell no deja activar el entorno, ejecuta una vez Set-ExecutionPolicy -Scope CurrentUser RemoteSigned y vuelve a intentarlo.

Cada vez que abras una ventana nueva tendrás que volver a activar el entorno y entrar a la carpeta de scripts:

Tu PCPowerShell · al empezar cada sesión
cd C:\practica-dask
.\venv\Scripts\Activate.ps1
cd scripts
02

Configura config.py

El único archivo que tienes que editar. Todos los demás scripts leen de aquí.

Abre scripts\config.py con VS Code o con el Bloc de notas y cambia solo la parte de arriba. Con los datos que escribiste al principio de la página, debe quedar así:

Tu PCscripts\config.py
# ======================= EDITA SOLO ESTA PARTE =======================
MODO = "cluster"
SCHEDULER = "tcp://192.168.1.10:8786"
DATOS_CLUSTER = r"\\192.168.1.10\datos\grupo01"
DATOS_LOCAL = r"datos"
# =====================================================================

MODO = "cluster"

Usa el cluster de la clase. Los datos tienen que estar en la carpeta compartida para que los workers los lean.

MODO = "local"

Crea un mini cluster dentro de tu PC. Sirve para practicar en casa, con los datos en scripts\datos.

¿Por qué la ruta empieza con \\?Los que leen los archivos son los workers, no tu PC. Una ruta como C:\datos o Z:\ solo existe en tu máquina. La ruta de red \\IP\carpeta es la misma para todas las PCs.

Particiones

Dask corta los datos en trozos llamados particiones. Cada worker procesa algunos trozos al mismo tiempo que los demás. Por eso varias PCs pueden trabajar a la vez.

Evaluación perezosa

dd.read_csv(...) no lee nada: solo arma un plan. El trabajo real empieza cuando pides un resultado con .compute(), len() o .head().

¿Por qué head() es rápido?

Solo necesita leer el primer trozo del primer archivo.

¿Por qué len() tarda más?

Para contar las filas tiene que leer los 12 archivos completos. Mira el panel web mientras se ejecuta.

Las dos ideas clave del script

Fragmento de 03_calidad.py
# 1. dd.compute(a, b, c) calcula todo leyendo los datos UNA sola vez
filas, vacios, devoluciones, duplicadas, sin_cliente = dd.compute(
    ventas.shape[0],
    ventas["monto"].isna().sum(),
    (ventas["monto"] < 0).sum(),
    # 2. map_partitions: aplica una función de pandas a cada trozo por separado.
    #    Los duplicados siempre están en el mismo mes, así que no hay que
    #    comparar filas de trozos distintos (eso sería mucho más lento).
    ventas.map_partitions(lambda p: p.duplicated(subset="id_venta").sum()).sum(),
    ventas["cliente_id"].isna().sum(),
)

07

Limpia y guarda en Parquet

Los workers limpian cada trozo en paralelo y lo guardan en un formato mucho más rápido.

Tu PCPowerShell · en scripts
python 04_limpiar.py

Qué hace, línea por línea

Fragmento de 04_limpiar.py
# 1. Quitar ventas sin monto
ventas = ventas.dropna(subset=["monto"])

# 2. Quitar duplicados dentro de cada mes
ventas = ventas.map_partitions(lambda p: p.drop_duplicates(subset="id_venta"))

# 3. " ALIMENTOS", "alimentos " y "Alimentos" pasan a ser "Alimentos"
ventas["categoria"] = ventas["categoria"].str.strip().str.capitalize()

# 4. Columnas nuevas para el análisis
ventas["anio"] = ventas["fecha"].dt.year
ventas["mes"] = ventas["fecha"].dt.month
ventas["es_devolucion"] = ventas["monto"] < 0

# 5. Guardar: cada worker escribe sus propios trozos en la carpeta compartida
ventas.to_parquet(ruta("ventas_limpias"), write_index=False, overwrite=True)

¿Por qué no borramos las devoluciones?

Son información real. Las marcamos con es_devolucion para separarlas cuando analicemos las ventas y para estudiarlas aparte.

¿Por qué Parquet?

Guarda los datos por columnas, comprimidos y con su tipo. Ocupa menos, se lee varias veces más rápido y puedes leer solo las columnas que necesitas.

Carga los datos limpios en la memoria de los workers una sola vez. Las preguntas siguientes ya no leen el disco y tardan menos de un segundo.

Cada worker resume sus trozos y Dask combina los resúmenes parciales. A tu PC solo llega una tabla pequeña con el resultado.

Tabla grande + tabla pequeña

Las ventas tienen 9 millones de filas y las tiendas solo 40. Dask envía la tabla pequeña a cada worker, que la une con sus trozos de ventas sin mover datos entre PCs. Esto se llama broadcast join.

Pandas para lo pequeño

tiendas.csv se lee con pandas normal. Usar Dask para 40 filas solo añadiría trabajo de coordinación.
