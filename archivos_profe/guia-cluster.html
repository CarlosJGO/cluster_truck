00

La idea general

Antes de tocar nada, entiende qué piezas vas a montar y cómo se hablan.

Un cluster de Dask tiene tres tipos de participantes. Piensa en una cocina de restaurante: alguien toma los pedidos, un jefe de cocina reparte el trabajo y varios cocineros cocinan al mismo tiempo.

Cliente

Tu PC con el script

Es donde escribes y ejecutas tu programa en Python. Le dice al scheduler qué trabajo hay que hacer y recibe los resultados.

Scheduler

El jefe de cocina

Hay uno solo. Divide el trabajo en tareas pequeñas, decide qué worker hace cada una y vigila que todo termine.

Worker

Los cocineros

Puede haber muchos, uno o varios por PC. Ejecutan las tareas con su CPU y su memoria y devuelven los resultados.

Puede ser la misma PCUna sola computadora puede ser a la vez cliente, scheduler y worker. Para empezar, lo normal es usar tu PC principal como scheduler y cliente, y las demás como workers.

Marca cada punto cuando lo tengas listo. Tu avance se guarda en este navegador.

02

Python y Dask iguales en todas

Si las versiones no coinciden, el cluster falla con errores difíciles de entender.

Primero prepara una PC (la del scheduler) y después copia exactamente esa misma instalación a las demás.

2.1 Comprueba la versión de Python

Todas las PCsPowerShell
python --version
Debe salir lo mismo en todas
Python 3.14.0

Si no tienes Python, descárgalo de python.org y, al instalarlo, marca la casilla “Add python.exe to PATH”.

2.2 Crea un entorno aislado

Un entorno virtual es una carpeta con su propio Python y sus propias librerías. Usa la misma ruta en todas las PCs para no confundirte.

Todas las PCsPowerShell
# Permite activar entornos virtuales (solo la primera vez)
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# Crea la carpeta del proyecto y el entorno
mkdir C:\dask
cd C:\dask
python -m venv venv

# Actívalo (verás "(venv)" al inicio de la línea)
.\venv\Scripts\Activate.ps1

2.3 Instala Dask en la primera PC y guarda las versiones

PC del schedulerPowerShell · con (venv) activo
pip install "dask[complete]" distributed pandas pyarrow

# Guarda la lista exacta de versiones instaladas
pip freeze > C:\dask\requisitos.txt

2.4 Instala lo mismo en los workers

Copia requisitos.txt a la carpeta C:\dask de cada worker (con una USB o por la carpeta compartida) y ejecuta:

Cada workerPowerShell · con (venv) activo
pip install -r C:\dask\requisitos.txt

# Comprueba: los números deben ser iguales en todas las PCs
python -c "import dask, distributed; print(dask.__version__, distributed.__version__)"
Regla de oroCualquier librería que use tu script (pandas, numpy, scikit-learn…) tiene que estar instalada en todos los workers, porque son ellos los que ejecutan el código. Si instalas algo nuevo, vuelve a generar requisitos.txt y repite la instalación en todas las PCs.

3.2 Marca la red como “Privada”

Windows bloquea casi todo en las redes “Públicas”. Pon la red como privada en todas las PCs:

Todas las PCsPowerShell como Administrador
# Ver el nombre y la categoría de tu red
Get-NetConnectionProfile

# Cambiarla a Privada (usa el InterfaceAlias que te salió arriba)
Set-NetConnectionProfile -InterfaceAlias "Ethernet" -NetworkCategory Private

3.3 Evita que las PCs se duerman

Si un worker entra en suspensión, el cluster lo pierde y las tareas en curso se repiten. En las PCs que hagan de worker o de scheduler:

Scheduler y workersPowerShell como Administrador
# 0 = nunca suspender (enchufada a la corriente)
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
IP fija para el schedulerLo más cómodo es entrar al router (normalmente 192.168.1.1) y hacer una “reserva DHCP” para la PC del scheduler. Así siempre recibe la misma IP y no tendrás que cambiar los comandos.
04

Abrir el firewall

Es la causa número uno de que “no conecta”. Hazlo con calma.

Dask usa estos puertos TCP. Vamos a fijar los puertos de los workers en un rango conocido para poder abrirlos en el firewall.

PuertoDóndePara qué
8786SchedulerClientes y workers se conectan aquí
8787SchedulerPanel web para ver el cluster en vivo
9000–9010WorkersEl scheduler y los otros workers les envían tareas y datos
9100–9110WorkersEl “nanny”, que vigila y reinicia cada proceso worker
PC del schedulerPowerShell como Administrador
New-NetFirewallRule -DisplayName "Dask Scheduler" -Direction Inbound `
  -Protocol TCP -LocalPort 8786,8787 -Action Allow -Profile Private
Cada workerPowerShell como Administrador
New-NetFirewallRule -DisplayName "Dask Worker" -Direction Inbound `
  -Protocol TCP -LocalPort 9000-9010,9100-9110 -Action Allow -Profile Private

Prueba la conexión antes de seguir

Este comando comprueba si un puerto responde. Funcionará cuando el scheduler esté encendido (paso 5), así que vuelve aquí si algo falla.

Desde un workerPowerShell
Test-NetConnection 192.168.1.10 -Port 8786
Lo que quieres ver
ComputerName     : 192.168.1.10
RemotePort       : 8786
TcpTestSucceeded : True
Si tienes otro antivirusProductos como ESET, Kaspersky o Norton tienen su propio firewall y la regla de Windows no basta. Añade allí la misma excepción para los puertos, o permite C:\dask\venv\Scripts\python.exe.
05

Encender el scheduler

Un solo comando en la PC coordinadora.

PC del schedulerPowerShell · con (venv) activo
cd C:\dask
.\venv\Scripts\Activate.ps1

dask scheduler --host 0.0.0.0 --port 8786 --dashboard-address :8787
Salida esperada
distributed.scheduler - INFO - -----------------------------------------------
distributed.scheduler - INFO -   Scheduler at:   tcp://192.168.1.10:8786
distributed.scheduler - INFO -   dashboard at:   http://192.168.1.10:8787/status
distributed.scheduler - INFO - -----------------------------------------------
  • --host 0.0.0.0 hace que escuche en todas las tarjetas de red, no solo en la propia PC.
  • No cierres esta ventana. Si la cierras, el cluster se apaga. Para detenerlo a propósito, pulsa Ctrl + C.
  • Ahora abre en el navegador http://192.168.1.10:8787/status. Verás el panel vacío, todavía sin workers.
06

Conectar los workers

Repite esto en cada PC que vaya a trabajar.

Cada workerPowerShell · con (venv) activo
cd C:\dask
.\venv\Scripts\Activate.ps1

dask worker tcp://192.168.1.10:8786 `
  --nworkers 2 --nthreads 2 --memory-limit 6GB `
  --worker-port 9000:9010 --nanny-port 9100:9110 `
  --host 192.168.1.21 --name $env:COMPUTERNAME
Salida esperada
distributed.worker - INFO -       Start worker at:  tcp://192.168.1.21:9000
distributed.worker - INFO - Waiting to connect to:  tcp://192.168.1.10:8786
distributed.worker - INFO -         Registered to:  tcp://192.168.1.10:8786

¿Qué significa cada opción?

OpciónQué haceCómo elegir el valor
--nworkersCuántos procesos worker arranca en esa PCNúcleos ÷ 2 es un buen inicio. Con 8 núcleos, pon 4.
--nthreadsHilos dentro de cada proceso2 suele ir bien. Para pandas puro, usa más procesos y menos hilos.
--memory-limitRAM máxima por proceso(RAM total − 2 GB para Windows) ÷ nworkers. Con 16 GB y 2 procesos, pon 6GB.
--worker-portPuertos fijos para los procesosDebe coincidir con lo que abriste en el firewall.
--hostIP propia por la que lo contactanLa IP de esta PC. Evita que Dask elija una tarjeta de red equivocada (VPN, VirtualBox…).
--nameNombre visible en el panel$env:COMPUTERNAME usa el nombre de la PC.
La PC del scheduler también puede trabajarAbre otra ventana de PowerShell en esa PC y lanza también un worker. Usa menos memoria allí, porque el scheduler y tu script también la necesitan.
07

Comprobar que funciona

Un script corto confirma que todos los workers responden.

Guarda este archivo como C:\dask\probar_cluster.py en la PC cliente:

PC clienteprobar_cluster.py
from dask.distributed import Client
import socket

def quien_soy(x):
    # Esta función se ejecuta en los workers, no en tu PC
    return socket.gethostname(), x * x

if __name__ == "__main__":
    client = Client("tcp://192.168.1.10:8786")

    info = client.scheduler_info()["workers"]
    print(f"Workers conectados: {len(info)}")
    for direccion, w in info.items():
        print(f"  {w['name']:<20} {direccion}  hilos={w['nthreads']}")

    # Revisa que todos tengan las mismas versiones
    client.get_versions(check=True)

    # Envía 40 tareas y mira qué PC resolvió cada una
    futuros = client.map(quien_soy, range(40))
    for pc, valor in client.gather(futuros)[:8]:
        print(f"  {pc} calculó {valor}")

    client.close()

08

Compartir los datos

Cada worker lee los archivos por su cuenta, así que todos deben poder llegar a ellos.

Este es el error más común: el script dice C:\datos\ventas.csv, pero esa ruta solo existe en tu PC. Los workers buscan en su disco C: y no encuentran nada.

Opción sencilla: una carpeta compartida de Windows

  1. En la PC que guarda los datos, crea C:\datos y pon ahí tus archivos.
  2. Compártela con permiso de lectura para los usuarios que usarán los workers.
  3. En el código usa siempre la ruta de red completa (UNC), no una letra de unidad como Z:.
PC con los datosPowerShell como Administrador
mkdir C:\datos
New-SmbShare -Name "datos" -Path "C:\datos" -ReadAccess "Todos"
# En Windows en inglés el grupo se llama "Everyone"
Desde cada workerPowerShell
# Debe listar los archivos. Si pide contraseña o falla, revisa los permisos.
dir \\192.168.1.10\datos
Dónde guardar los datosCuándo convieneRuta en el código
Carpeta compartida / NASOficina pequeña, de MB a decenas de GBr"\\servidor\datos\*.csv"
Base de datos (PostgreSQL, SQL Server)Los datos ya están en una basedd.read_sql_table(...)
MinIO o S3Mucho volumen o PCs en sitios distintos"s3://bucket/ventas/*.parquet"
Usa Parquet para datos grandesConvierte tus CSV a Parquet una vez. Ocupa mucho menos, se lee varias veces más rápido y guarda los tipos de columna. Lo verás en el siguiente paso.
09

Tu primer trabajo real

Leer muchos CSV, limpiarlos, resumirlos y guardar el resultado, usando todo el cluster.

Supongamos que en la carpeta compartida hay archivos ventas_2025_01.csv, ventas_2025_02.csv… con las columnas fecha, tienda, categoria, monto.

PC clienteprocesar_ventas.py
import time
import dask.dataframe as dd
from dask.distributed import Client, progress

SCHEDULER = "tcp://192.168.1.10:8786"
DATOS     = r"\\192.168.1.10\datos"

if __name__ == "__main__":
    client = Client(SCHEDULER)
    print("Panel:", client.dashboard_link)
    inicio = time.time()

    # 1. Leer: Dask crea una partición por archivo (o por bloque)
    df = dd.read_csv(
        DATOS + r"\ventas_*.csv",
        dtype={"tienda": "string", "categoria": "string", "monto": "float64"},
        parse_dates=["fecha"],
        blocksize="64MB",
    )

    # 2. Limpiar y transformar (todavía no se calcula nada: es "perezoso")
    df = df.dropna(subset=["monto"])
    df = df[df["monto"] > 0]
    df["mes"] = df["fecha"].dt.to_period("M").astype("string")

    # 3. Guardar una copia limpia en Parquet (lo hacen los workers en paralelo)
    df.to_parquet(DATOS + r"\ventas_limpias", write_index=False, overwrite=True)

    # 4. Resumir. Con .persist() los datos quedan en la memoria del cluster
    limpio = dd.read_parquet(DATOS + r"\ventas_limpias").persist()
    progress(limpio)

    por_categoria = limpio.groupby("categoria")["monto"].agg(["sum", "mean", "count"])
    por_mes       = limpio.groupby(["mes", "tienda"])["monto"].sum()

    # 5. .compute() trae el resultado pequeño a tu PC como DataFrame de pandas
    resumen = por_categoria.compute().sort_values("sum", ascending=False)
    print(resumen.head(10))
    por_mes.compute().to_csv(DATOS + r"\resumen_por_mes.csv")

    print(f"Listo en {time.time() - inicio:.1f} s")
    client.close()

Tres ideas clave para entender el código

  • Evaluación perezosa. Las operaciones solo arman un plan. El trabajo empieza al llamar a .compute(), .persist() o .to_parquet().
  • Particiones. Dask divide el DataFrame en trozos y cada worker procesa algunos. Apunta a particiones de 50 a 200 MB.
  • Trae a tu PC solo lo pequeño. .compute() sobre millones de filas puede llenar la memoria del cliente. Resume primero o guarda en disco.

¿Usas tus propias funciones en otro archivo?

Si tu script importa un módulo tuyo (por ejemplo utilidades.py), los workers no lo tienen. Envíaselo así:

PC clientePython
client.upload_file(r"C:\dask\utilidades.py")
# Ahora los workers pueden ejecutar funciones de utilidades.py
10

Arranque automático

Para no abrir PowerShell a mano en cada PC cada día.

10.1 Crea un archivo .bat en cada máquina

PC del schedulerC:\dask\iniciar_scheduler.bat
@echo off
cd /d C:\dask
call venv\Scripts\activate.bat
dask scheduler --host 0.0.0.0 --port 8786 --dashboard-address :8787 >> C:\dask\scheduler.log 2>&1
Cada workerC:\dask\iniciar_worker.bat
@echo off
cd /d C:\dask
call venv\Scripts\activate.bat
:: Espera 30 s a que la red esté lista
timeout /t 30 /nobreak >nul
dask worker tcp://192.168.1.10:8786 --nworkers 2 --nthreads 2 --memory-limit 6GB --worker-port 9000:9010 --nanny-port 9100:9110 --host 192.168.1.21 --name %COMPUTERNAME% >> C:\dask\worker.log 2>&1

Prueba primero cada .bat con doble clic. Si funciona, prográmalo para que arranque solo.

10.2 Prográmalo con el Programador de tareas

Cada workerPowerShell como Administrador
schtasks /Create /TN "Dask Worker" /TR "C:\dask\iniciar_worker.bat" `
  /SC ONLOGON /RL HIGHEST /F

En la PC del scheduler, haz lo mismo cambiando el nombre de la tarea y el archivo por iniciar_scheduler.bat. Con ONLOGON arranca al iniciar sesión, usando tu usuario, que ya tiene acceso a la carpeta compartida.

Revisa los registrosSi algo no arranca, abre C:\dask\worker.log o C:\dask\scheduler.log. El error casi siempre aparece en las últimas líneas.

Si algo falla

Los errores más frecuentes y cómo resolverlos.

SíntomaCausa probableSolución

Seguridad

Un cluster de Dask ejecuta cualquier código que le envíen.

Nunca expongas los puertos a InternetCualquiera que llegue al puerto 8786 puede ejecutar programas en todas tus PCs. Por eso las reglas del firewall de esta guía usan -Profile Private. No abras estos puertos en el router.
  • Usa el cluster solo dentro de tu red local o a través de una VPN.
  • Da a la carpeta compartida solo permisos de lectura, salvo la subcarpeta donde se guardan resultados.
  • Si la red la comparten personas que no conoces, activa el cifrado TLS de Dask con certificados. Consulta la sección “TLS/SSL” de la documentación oficial.
  • Apaga el scheduler (Ctrl + C) cuando no lo uses.
